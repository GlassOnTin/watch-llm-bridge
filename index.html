Watch → LLM Bridge

A self-hosted voice hub: an Apple Watch shortcut dictates a command and POSTs it to your endpoint. An LLM with tool-calling routes it into Trello and Google Calendar. No Zapier, no subscription glue.

The watch side never changes: Dictate Text → Get Contents of URL (POST) → Speak Text. All intelligence lives on the server, so you iterate there without touching the shortcut.

01The watch shortcut

Build this in the Shortcuts app on iPhone, then enable Show on Apple Watch. Pin it as a watch complication, or assign it to the Ultra's Action button for a literal hardware button.

  1. Dictate Text — language set to your preference. This is the only practical STT on watchOS; it runs through Apple's servers.
  2. Get Contents of URL — URL https://your-endpoint.example/command, Method POST, Headers:
    • Content-Type: application/json
    • Authorization: Bearer <your token>
    Request Body → JSON: a field text with the Dictated Text magic variable.
  3. Get Dictionary Value for key reply (from the response).
  4. Speak Text on that value.

Tip: for slow jobs (LLM latency, long calendar reads), have the server reply fast and deliver results later via a push notification — Shortcuts blocks on the HTTP response.

02The endpoint

One small FastAPI service. Phase 1 is transport + auth + echo, so you can verify the whole round trip before any LLM code exists. Anything not built yet raises NotImplementedError on purpose — a stub that returned fake data would silently corrupt your assumptions.

server.py — Phase 1
# pip install fastapi "uvicorn[standard]"
# BRIDGE_TOKEN=$(openssl rand -hex 24) uvicorn server:app --host 0.0.0.0 --port 8000
import os
from fastapi import FastAPI, Header, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel

TOKEN = os.environ["BRIDGE_TOKEN"]

app = FastAPI()
# CORS is only needed for the endpoint tester on this page. Lock the origin
# to this page's URL once you know it; omit entirely if you never use the tester.
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://glasontin.github.io"],
    allow_methods=["POST", "GET"],
    allow_headers=["Authorization", "Content-Type"],
)

class Command(BaseModel):
    text: str

@app.get("/health")
def health():
    return {"ok": True}

@app.post("/command")
def command(cmd: Command, authorization: str = Header(default="")):
    if authorization != f"Bearer {TOKEN}":
        raise HTTPException(status_code=401, detail="bad token")
    return {"reply": route(cmd.text)}

def route(text: str) -> str:
    """Phase 1: echo, so the watch round-trip is verifiable end to end.
    Phase 2 replaces this body with an LLM that selects tools (see #llm)."""
    return f"echo: {text}"

Exposing it: a Hetzner cpx instance with Caddy/Nginx for TLS, or your home server behind a Cloudflare Tunnel — both work. The only hard requirement is HTTPS, because Shortcuts sends the bearer token on every request.

03Trello

Key/token auth, confirmed working as of 2026. The flow changed in one way: API keys are now generated through a Power-Up.

  1. Create a Power-Up at trello.com/apps/admin (a stub Power-Up with no features is fine — you only want its API key tab).
  2. Authorize a token with the longest expiry, in a browser:
    authorize URL
    https://trello.com/1/authorize?expiration=never&name=WatchBridge&scope=read,write&response_type=token&key=YOUR_API_KEY
    Use expiration=30days if you prefer a rotation story, but 1day will break the service silently.
  3. Verify credentials and fetch your board's list IDs (cache these at server startup; they don't change often):
    shell
    # sanity check
curl -s "https://api.trello.com/1/members/me?key=$TRELLO_KEY&token=$TRELLO_TOKEN" | jq .username

# boards
curl -s "https://api.trello.com/1/members/me/boards?key=$TRELLO_KEY&token=$TRELLO_TOKEN" | jq '.[] | {name, id}'

# lists on a board  →  this is what the LLM routes cards into
curl -s "https://api.trello.com/1/boards/$BOARD_ID/lists?key=$TRELLO_KEY&token=$TRELLO_TOKEN" | jq '.[] | {name, id}'
  4. Create a card:
    shell
    curl -s -X POST \
  "https://api.trello.com/1/cards?idList=$LIST_ID&name=Test%20card&key=$TRELLO_KEY&token=$TRELLO_TOKEN" \
  | jq '{name, id, url}'
Rate limits: 100 requests / 10 s per token — irrelevant at human command pace, but worth knowing if you ever batch.

04Google Calendar

  1. Google Cloud project → enable the Calendar API.
  2. OAuth consent screen: External, add scope calendar.events, add yourself as a test user.
  3. Publish the app to production (Audience → Publish app). This does not require completing verification. See the warning below for why this matters.
  4. Run a desktop OAuth flow once on any machine, store the resulting refresh token on the server. The server mints short-lived access tokens from it automatically.
The 7-day trap. With the consent screen in Testing status, Google expires your refresh token after exactly 7 days (invalid_grant). Publishing to In production without completing verification removes the expiry — you'll just see a "Google hasn't verified this app" warning once during the consent flow. The change is not retroactive: re-run the OAuth flow after publishing, and check for an absent refresh_token_expires_in field to confirm.

Other things that kill a refresh token: six months of disuse (only a token exchange counts), revoking access, changing scopes, or password changes on Gmail-scoped apps.

05The LLM layer

Replace route() with an LLM call that exposes a small, fixed tool set. The tools map 1:1 onto the real APIs; the model never invents endpoints.

ToolMaps toUsed for
trello_create_card(board, list, name, desc?)POST /1/cards"add a task to plan the week"
trello_list_cards(board, list)GET /1/lists/{id}/cards"read out my to-do list"
trello_move_card(card, to_list)PUT /1/cards/{id}"move that to Done"
gcal_list_events(day)events.list"what's on tomorrow"
gcal_create_event(summary, start, end)events.insert"book the dentist Tuesday 2pm"

System prompt carries your board's list names, so "put this in the right list" resolves from a known set rather than guessing. Ambiguity ("which board?") should come back as a spoken question, not a guess.

Model choice: any tool-calling endpoint works. A local ollama model is adequate for routing among a handful of well-described tools; hosted APIs are lower-latency. The tool interface is identical either way.

Self-hosted by design: one bearer token on the wire, credentials stay on your server, no third-party automation platform in the path.
